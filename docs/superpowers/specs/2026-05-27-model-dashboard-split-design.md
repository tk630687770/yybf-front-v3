# Model Dashboard Split Design

## 目标

将当前“模型预测/诊断结果台”拆成三个职责明确的页面，避免预测、复盘、诊断结果在同一个页面中不断追加区域。

## 页面拆分

### 实时预测台

路径：`/prediction-console`

职责：

- 展示当前开奖上下文。
- 刷新下一期预测。
- 展示主推荐票面、9+1复式方案、10注6+1单式方案。
- 复制购买内容。
- 保存下一期预测快照。
- 保留红球组合候选榜、蓝球候选榜、红蓝合并明细作为默认折叠的解释材料。

不负责：

- 多期趋势。
- 漏号分布。
- 保底回测。
- 诊断包保存。

### 快照复盘台

路径：`/snapshot-review`

职责：

- 展示当前开奖上下文。
- 读取最近预测快照。
- 查看快照和复盘快照。
- 在原票面区域直接标记命中号码、奖级、奖金。
- 保存诊断包。

不负责：

- 直接展示多期趋势、贝叶斯、漏号分布、保底扩展等研究区块。

### 诊断研究台

路径：`/diagnostic-lab`

职责：

- 展示研究诊断操作入口。
- 运行贝叶斯冷热、多期复盘趋势、多期漏号统计、保底扩展回测、配额保底回测。
- 展示对应诊断区域。

不负责：

- 作为购买票面主入口。
- 保存预测快照。

## 实现策略

第一阶段不复制三份大组件，也不立刻把 `ModelDashboard.vue` 拆成大量子组件。

采用：

```text
三条路由 -> 同一个 ModelDashboard.vue -> 根据 route.name 判断 pageMode -> 条件展示不同区块
```

这样可以先获得清晰页面边界，同时保留现有数据加载、复制、复盘、命中标色逻辑。

后续第二阶段再根据稳定边界把公共逻辑提取为 composable，把展示区块拆成子组件。

## 成功标准

- 顶部导航出现：基础窗口操作台、实时预测台、快照复盘台、诊断研究台。
- 旧路径 `/model-dashboard` 自动跳转到 `/prediction-console`。
- 实时预测台只展示预测和购买彩票相关区域。
- 快照复盘台只展示快照、复盘和诊断包保存相关区域。
- 诊断研究台只展示诊断操作和诊断结果区域。
- `npm run build` 通过。
