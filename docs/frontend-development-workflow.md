# 前端开发流程与进度记录

## 文档目标

这份文档用于提醒后续开发者和 Codex：前端不只是页面展示层，它已经承担“窗口观察、预测输出、开奖复盘、诊断研究”四条链路。每次修改前需要先判断改动落在哪条链路，避免页面继续膨胀或误伤开奖前快照证据链。

## 当前页面入口

| 路由 | 页面 | 主要职责 |
|------|------|----------|
| `/window-console` | 基础窗口操作台 | 本地窗口数据、窗口状态、窗口矩阵、人工模拟和号码联动 |
| `/prediction-console` | 实时预测台 | 开奖前预测展示、9+1复式、10注6+1单式、保存预测快照 |
| `/snapshot-review` | 快照复盘台 | 开奖后读取快照、复盘、保存诊断包 |
| `/diagnostic-lab` | 诊断研究台 | 多期趋势、漏号统计、贝叶斯冷热、保底扩展、配额回测 |
| `/historical-replay-lab` | 历史回放实验台 | 按开奖前视角批量回放历史期号，保存和读取策略实验结果 |

旧入口 `/model-dashboard` 保留为兼容入口，目前重定向到 `/prediction-console`。

## 当前进度

### 批次计划

后续模型预测与诊断页面改造按以下批次推进，避免把解释优化、红球漏斗、蓝球诊断和策略准入混在一起：

1. 第一批：诊断解释优化 + 开奖后流程自动化提示。
   - 目标：让页面先能看懂、流程先不乱。
   - 状态：已完成“开奖后执行链”“诊断阅读顺序”“诊断指标速读”。
2. 第二批：候选池阶段漏斗增强。
   - 目标：围绕 `红10入口 -> 组合池 -> 保底扩展池 -> 压缩9红 -> 10注票面`，看清真实红球在哪一层被丢掉。
   - 状态：已完成并验证。
3. 第三批：蓝球独立诊断设计与开发。
   - 目标：独立判断蓝球候选源头、蓝尾、重邻号、遗漏区间、贝叶斯蓝球等问题。
   - 状态：已完成并验证。已新增蓝球候选池独立诊断接口和诊断研究台展示，验证通过后端编译、接口响应和前端页面按钮展开。
4. 第四批：策略准入规则和文档纪律。
   - 目标：写清楚观察策略什么时候可以升级为正式预测，避免靠单期感觉调整模型。
   - 状态：已完成并验证。已在诊断研究台补充策略准入提示，并通过前端构建和页面展示验证。

### 进行中

- `ModelDashboard.vue` 仍是复用页面组件，内部通过路由模式切换预测、复盘和诊断内容。
- 这是低风险拆页阶段的结果；快照复盘台的部分展示组件已经先行拆出，后续仍应继续拆预测票面、诊断区块和接口状态 composable。

## 开发流程

1. 先判断改动属于哪条链路：窗口、预测、复盘、诊断。
2. 阅读相关文档和最近的设计/计划文件。
3. 如果需求会影响开奖前快照或历史复盘真实性，先确认再动手。
4. 修改代码时保持中文注释，重要计算、状态切换和接口语义必须说明用途。
5. 修改页面后运行 `npm run build`。
6. 涉及路由、按钮、折叠、复制、复盘或诊断展示时，用浏览器验证。
7. 如果改动影响页面职责、流程、接口或阶段性结论，更新本文档或 `docs/frontend-module-plan.md`。
8. 如果页面出现中文乱码，先检查后端响应头是否包含 `application/json;charset=UTF-8`，再检查是否曾由脚本客户端误解码后保存了污染快照。

## 复盘与预测相关纪律

- 开奖后复盘必须使用开奖前保存的快照，不能用当前模型重新计算上一期预测。
- 实时预测台用于生成和保存下一期快照，不应自动切换成历史快照页面。
- 快照复盘台用于查看历史快照和复盘，不应混入新的实时预测操作。
- 诊断研究台用于观察和回测，除非明确确认，不应直接改变正式预测输出。
- 配额网格回测只用于寻找保底观察线；若要进入正式预测，必须先记录策略决策并提升模型版本。
